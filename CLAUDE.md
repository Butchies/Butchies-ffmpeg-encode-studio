# Notizen für Claude – ffmpeg_encode Studio
Windows-Programm: Song + Bild → YouTube-Video (4K/1440p/1080p, Shorts 9:16, Shorts 4K). Nutzer schreibt Deutsch, technisch unerfahren – einfach erklären.

## Aufbau
- `ffmpeg_encode_studio.py`: Python-stdlib-Server auf 127.0.0.1 (Token im URL-Hash, Header `X-Studio`), pywebview/WebView2-Fenster (rahmenlos, `WinFrame`), Fallback Edge/Chrome-App-Fenster.
- Bild wird einmal per `still_command` auf Zielgröße gebracht (Fit: blur/cover/contain), dann im Video per `loop`-Filter wiederholt (schneller als `-loop 1`).
- Übergänge: `TRANSITIONS` (36, FFmpeg `xfade`) über `transition_graph` – Farbe→Bild (Bild kommt) und Bild→Farbe (Bild geht); Ton-Fades per `afade`. Vorschau-Clip `/api/trans-preview`.
- Encoder: `auto` = erste funktionierende Grafikkarte (`GPU_ORDER` nvenc, qsv, amf; Test in `hw_check`), sonst x264; scheitert die GPU, automatischer Rückfall auf x264 (`run_job`).
- Visualizer `viz.py` (seit 1.1.0): 20 Stile (`STYLES`), Farbarten solid/gradient/rainbow/random/sound, freie Position `vizX/Y/W/H` in % + Andockplatz `vizDock` (UI rechnet Position), Regler vizStr/Alpha/Glow/Dens/Smooth/Line, Schalter vizCenter/Floor/Soft. Graph: Ton -> Graustufen -> Leuchten (halbtransparent, `lighten`) -> Alpha (Deckkraft, weiche Ränder) + Farbverlauf (`gradients`) -> `alphamerge` -> overlay. „Nach Sound“: `sound_commands` (reines Python, RMS + Nulldurchgänge) -> sendcmd-Datei im Arbeitsordner (FFmpeg läuft mit cwd=STAGE). ACHTUNG: kein `fps`-Filter direkt nach showwaves (Speicher läuft voll); Spektrum-Höhe über höher rendern + crop (`stretch`).
- Markieren (1.2.0, `mark.py`): `vizShape` box/mask/path, `vizMask` (Token, PNG ganzes Bild → Ausschnitt bbox), `vizPath` (normiert) + `vizClosed`/`vizBoth`/`vizThick`/`vizFeather` = `MARK_KEYS` (nicht in Vorlagen, aber in Projekten inkl. maske.png). Pfad: Streifen L×T rendern, mit `remap` (xmap/ymap PGM16) biegen. Endpunkte `/api/mark/mask|segment|refine|suggest`. KI: MobileSAM ONNX (`models/`, im Workflow von HF Acly/MobileSAM geladen) über onnxruntime(-directml); ohne Modell GrabCut-Ersatz. UI: `MK`-Objekt in app.js, `#markBar`, `#markCanvas` (Maske 960×540 bzw. 540×960), `#markSvg`. Eigener Doppelklick (nicht `e.detail`).
- Bild-Effekte (1.3.0, `fx.py`): `fx` (10 inkl. none) + `cam` (none/zoom/pan/depth). Partikel = nahtlose Graustufen-Felder (numpy, `stamp` mit Umlauf), mehrere Ebenen untereinander in EINEM PNG, im Graph `crop` je Ebene + `scroll` (positiv = Inhalt nach links/oben) + `blend`; Farbe per `gradients` + `alphamerge` + overlay. Lichtlinien auf Pfad: Streifen, Linie = UNTERSTE Zeile (remap spiegelt beidseitig), Enden ausblenden. Fließen/3D: `displace` in gbrp, Karten als gray erzeugen und erst nach scale `format=gbrp` (exakt). Zoom/Schwenk: `perspective` mit `on`. Im Takt: `color@fxb` + sendcmd (gemeinsame Datei mit viz „Nach Sound“, `needs_sound`), multipliziert die Deckkraft. Markierung fürs Effekt: `fxArea` full/mask/path + fxMask/fxPath… (`fx.MARK_KEYS`). Tiefen-KI `models/depth_anything_v2_small.onnx` (`fx.Depth`), sonst `simple_depth`. UI: `MK.target` viz/fx, Proxy `M` (M.Path = vizPath/fxPath), `shp()/setShp()`, `#fxCanvas` Skizze (`fxFrame`), Karte `#fxCard`, GPU-Anzeige `gpu_view`. GPU-Erkennung `detect_gpus` (Registry + nvidia-smi).
- 1.6.0: `highlight.py` (numpy: Onsets, Tempo+Ellis-Beat-Tracking, Energie, Chroma-Selbstähnlichkeit -> `suggest` Refrain/Drop/Emotional, Start auf Taktanfang −0,03 s, Ende = Start+Länge), Jobs `/api/highlight` (POST startet, GET `/api/highlight/<id>` Fortschritt), Cache `HL_CACHE`. `lyrics.py` = faster-whisper „base“ int8 (Modell seit 1.6.1 im Installer (`models/whisper-base`, Workflow lädt es von HF Systran/faster-whisper-base); Ersatz-Download nach `%APPDATA%/…/models/whisper-base` nur falls es fehlt, `/api/lyrics/status|download`), PyAV per Stub-Modul ersetzt, im Workflow `faster-whisper --no-deps` + ctranslate2/tokenizers/huggingface_hub/tqdm. UI: `#shortExt` im Zielformat (nur Shorts, `shortLen`/`shortLyrics`), `renderShort`/`renderHl`. Vollbild: `toggle_full` NICHT topmost (HWND_TOP), `next_monitor`, `fit_full` (bei resize), Knöpfe `#winFull`/`#winMon`. Name „Butchies Encode Studio AI“ NUR im Start-/Abschiedsbildschirm (`.ai-mark`, Schimmer in --a/--b), sonst bleibt „ffmpeg_encode Studio“ (Nutzerwunsch). KI-Video-Kachel `.fxtile.ai-tile` -> `openAiCard()` (seit 1.8.0).

- 1.4.0: Karten mit `data-fold` (fmt/fit/viz/fade) + `#markBar` einklappbar, beim Start zu (`setupFolds`, `foldToggle`, Zusammenfassung `FOLD_SUM`/`foldSummaries` in `changed`). - 1.8.0 KI-Video (`aivideo.py`, `AIV`): stable-diffusion.cpp `sd-cli` (Vulkan-Release von leejet, im Workflow nach `dist/.../sdcpp/`, Test-Ersatz per `BES_SDCLI`) + Wan2.2-TI2V-5B-Turbo Q4_K_M GGUF (hum-ma) + umt5 Q4_K_M (city96) + Wan2.2_VAE (QuantStack) = ca. 8 GB, Download auf Wunsch nach `HOME/aivideo/models` (Dateinamen über HF-API aufgelöst, `manifest.json`, Range-Wiederaufnahme; `BES_AIMODELS`). Turbo: 4 Schritte, CFG 1, euler, flow-shift 5, 24 fps, Größen Vielfache von 32 (`QUALITIES` fast 832×480/97 Bilder, good 1280×704/121). Ausgabe als PNG-Folge (`-o f_%04d.png`), je Stück `segment-XXX.mp4` + `-last.png` + `.log` in `jobs/<key>/seed-<n>/` (key = Bild-Hash+fit+Qualität+Bewegung+Text+Hochformat). `plan()`: Kette (Start = letztes Bild), alle `ANCHOR`=6 Stücke Start beim Original mit `XFADE`-Überblendung, Ende zurück zum Original (nahtlose Schleife); `assemble` per numpy-Pipe. Einstellungen `ai/aiClip/aiArea/aiMask/aiFeather/aiMotion/aiText/aiLen/aiQual`; `ai_graph` in `encode_command` VOR den Effekten: `-stream_loop -1`, ganz ersetzen oder `maskedmerge` (gbrp) mit Maske. Endpunkte `/api/ai/status|info|start|job/<id>|cancel|download|remove|video?p=`. UI: Karte `#aiCard` (`renderAi`, `aiInfo`, `aiStart`, `aiPollJob`), Markier-Ziel `MK.target='ai'` (nur Kasten/Fläche). Echttest mit echtem Modell: Workflow `aivideo-test.yml` + `tools/aivideo_test.py` (winzige Größe auf CPU, Artefakt `ki-video-test`).

## Build / Release
- Push auf `main` → Workflow `encoder-exe.yml` (windows-latest): PyInstaller onedir, FFmpeg GPL-shared von BtbN, WebView2-Bootstrapper, Echttest `tools/smoke.ps1` (Videos + KI-Auswahl muss `method=ki` liefern + Masken-/Ring-/Linien-Videos), Inno Setup → Release `encoder-v<VERSION>` mit `ffmpeg_encode_Studio-Setup.exe`.
- Neue Version: `VERSION` in `ffmpeg_encode_studio.py` erhöhen (gleiche Version = Datei im Release wird ersetzt).
- Lokal testen: `python3 ffmpeg_encode_studio.py --no-window` + Playwright (`/usr/bin/google-chrome`).
- Nutzerwunsch: bei Releases Fortschritt in Prozent (ca. alle 5 %) angeben.
